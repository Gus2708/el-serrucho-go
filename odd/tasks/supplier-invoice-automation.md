### T4 implementation contract

Accepted design: additive `facturas_proveedores_revisiones` references immutable extraction results. Preserve the existing save RPC, controller and device recovery schema. Explicit server saves and an unsaved-edit close guard protect review recovery. Show original/corrected/normalized values distinctly; motivated corrections retain literal codes and stable per-source UUIDs, including repeated SKUs. Applying another extraction is explicit, never automatic.

Persisted content v1 is defined by the [SQL validator](../../supabase/migrations/20261023140305_facturas_proveedores_revisiones.sql) and [RevisionContenido](../../src/lib/facturaRevision.ts): review_schema1/calc-v1/matching-v1, immutable extraction reference, header confirmations, corrections, stable source UUIDs, conversion, explicit association and barcode intention. Scalar corrections are string/null; discounts/taxes are complete typed arrays with motives, including explicit empty arrays, never JSON strings. Manual additions require a motive. Every extracted line remains represented exactly once across the entire per-source history. Replacing extraction requires a revision motive. Unknown fields/shape fail closed; reconcile contract changes before edits.

Storage: invoice/revision PK and per-invoice operation key; base version/document SHA, extraction FK, server fingerprint and author/time. Owner + active privileged + valid session RLS; no direct DML even service_role. Private fixed-search-path SECURITY DEFINER, authenticated invoker wrappers and existing invoice advisory lock. `guardar_revision_factura` validates structure/decisions, replays identical requests and rejects key/stale conflicts; `aprobar_revision_factura` attests latest unchanged source/version only. Exact signatures and errors are in the SQL above. Never trust client financial results/blocker arrays. UI recomputes before Validada; attestation is NOT purchase authority and T6 independently recomputes before transfer.

Domain: decimal strings with exact integer arithmetic, no binary floating-point monetary authority or new dependency. Ordered discounts apply once; percent plus amount is a consistency check, not two discounts; included discounts never reapplied. Exact examples: 10 × 0.80 × 0.95 = 7.60, then × 0.97 = 7.372; 0.10 across three equal eligible bases allocates 0.04/0.03/0.03 by stable line ID; 0.1234 × 1000 versus 0.12 × 1000 differs by 3.40. VAT is per line, including exempt; unknown inclusion/rates remain unknown. Unknown or unapproved FX, fiscal/rounding/tolerance/global eligibility/charges policies stay explicit blocks, not inferred defaults. Test-only injected policies are not production approval. Require confirmed units/conversion and document completeness/receipt; show printed/calculated differences. POS precision remains explicitly unverified and no purchase authority is granted by T4. Barcode collision checks must be exact and completeness-aware: an absent item in a capped candidate subset does not prove uniqueness. Do not treat unresolved matching as a new product.

App: explicit authorized click uses unchanged T2 request/validation. RLS reads; absent service/relation maps to unavailable without breaking manual entry. Never reinvoke/reserve automatically after409/uncertain outcome. Fence results by account/session/invoice/version and preserve edits. UI money is USD; other currency stays internal until approved conversion. No catalog/queue/purchase/product mutation, remote operations or live paid calls. Dependency junction is read-only: no installs/package/config edits. Generate source migration with installed CLI, never apply remotely. Initial1600–2200 forecast underestimated tests/domain: storage alone1938lines; revise fullT4 forecast6000–9000, provisional. Cached auto-chain/feature-branch-chain; coherent overages need size:exception recommendation at future PR, not code-golf/test splitting. Parent owns git/tracker/mirror. RDD OFF; named risks still require independent verification.
